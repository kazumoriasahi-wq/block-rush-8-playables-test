BLOCK RUSH 8
Playables対応テスト版 α1

2026年10月17日。正式版V2.0のゲームルールを維持し、別のテスト環境にSDKの基礎統合を追加しました。

▶ SDK読み込み版を開く ／ SDK模擬テスト室を開く
YouTubeに公開済み・認証済みという意味ではありません。GitHub PagesではSDKは通常のブラウザー環境として動き、YouTube内の本物のクラウド保存や通知は検証できません。

正式版の保護

正式版 block-rush-8 と旧版バックアップは変更していません。SDK対応は専用リポジトリ block-rush-8-playables-test で行います。通常ブラウザーの保存名も br8_playables_alpha1 に分離し、正式版のスコアや盤面を読み書きしません。

実装した内容

項目動作
SDK読み込み公式 https://www.youtube.com/game_api/v1 をゲームコードより前に読み込み。ゲーム側でytgameを書き換えません。
起動通知読込画面でfirstFrameReady。保存データの読込が成功し、操作可能になってからgameReady。ホスト停止中なら再開まで初期化を待機。
クラウド保存Playables内ではloadData / saveDataのみ使用。通常ブラウザーでは専用localStorage。読込失敗・未知スキーマは上書きせず停止し、再試行ボタンを表示。保存失敗は通知し、進行を保持して次の保存時に再試行。
保存の順序読込前の保存を禁止。複数の書込を直列化し、処理中の新しい進行も最後に反映。停止時には最新状態を最終保存。日別ベストは直近14件、保存サイズは60,000バイト以下の保守的上限。
音声isAudioEnabledとonAudioEnabledChangeを使用。YouTubeミュート中は無音で、既存のAudioContextも閉じます。YouTube内ではゲームの全体ミュートボタンを非表示。
停止と再開onPauseで入力・効果音・演出のタイマーを停止、CSSアニメーションも停止。onResumeで復帰。ホスト停止をゲームの再開ボタンで解除できません。YouTube内ではVisibility APIやblurを停止制御に使いません。

実施済みの確認

  • ルール9項目、SDKアダプター12項目の自動テストが合格。
  • 通常ブラウザーで配置と加点。正式版と別の空盤面から開始。
  • 模擬SDKでfirstFrameReady → loadData → gameReadyの順序、配置後のクラウド保存呼出しを確認。
  • ホスト停止中に盤面が操作対象から外れ、再開で戻ることを確認。
  • 保存エラー時の通知、復旧後の再保存、読込失敗中にgameReadyとsaveDataが発生しないこと、復旧後に30点の盤面が復元されることを確認。
  • これらは独自の模擬環境による開発検証です。実際のYouTube上での合格結果ではありません。

iPhoneでの確認

  1. このテスト版のindex.htmlをSafariで開き、選択・タップ・ドラッグ、配置、消去、コンボ、デイリーを試す。
  2. Safariでは通常ブラウザー用の保存が使われます。再読込後の復元、タブを離れた際の停止と再開を確認。
  3. 模擬テスト室を開き、ゲームを1手進めてから「YouTube一時停止」「YouTube再開」を順番に押す。
  4. 「YouTubeミュート」後の無音、音声ON後に次の操作から音が出ることを耳で確認。
  5. 「保存失敗を再現」→ゲームで配置→通知を確認→「保存を復旧」→一時停止・再開で保存を再試行。
  6. 「次の読込を失敗」→「ゲームを再読込」でエラー画面とイベント記録を確認。「読込を復旧」→ゲーム内の「もう一度読み込む」で盤面が戻ることを確認。

YouTubeの審査前に残る作業

  • 公式Test Suiteと実際のYouTube環境での統合検証。公式Test Suiteのページは今回の環境では操作画面が表示されず、実行できていません。開発者ポータルへのアクセス資格と提出経路を確認する必要があります。
  • iOS / AndroidのYouTubeアプリ、ブラウザー、終了・再起動・アカウント切替における本物のクラウド保存と音声割り込みを検証。
  • 配信時のContent Security Policyを適用したブラウザー検証。SDK以外の外部素材・通信はありませんが、公式ヘッダーを付けた再検証は未実施。
  • 言語対応。現在のゲームUIは日本語です。getLanguageと表示文言の切替、および対象地域の要件を整理。
  • 任意のsendScoreは未実装。導入時は通常とデイリーのどちらを送るか決め、クラウド保存のベストと一致させる。
  • アクセシビリティ、低性能端末の性能、長時間プレイ、再試行時のUI、プライバシー・コンテンツ等の全認証要件を最終確認。
  • 広告・課金は追加していません。提出は別途承認された開発者経路で行い、申請フォームや契約への同意は今回実施していません。

提出用ZIPと開発用ZIP

BLOCK-RUSH-8-Playables-build.zip はルートindex.html、style.css、engine.js、platform.js、app.jsの5ファイルです。SDKモックやテスト室は含めません。審査提出の完了を意味するものではありません。

BLOCK-RUSH-8-Playables-source.zip は開発用一式です。自動テストは node tests.cjs と node tests/platform-tests.cjs。ローカル起動は node serve.cjs、表示先は http://127.0.0.1:4178/。
